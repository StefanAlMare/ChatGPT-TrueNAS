# ChatGPT Drop 0.9.0-rc15.1 — Update & Keychain Fix

**Notarized Intel macOS preview · build 16 · proprietary non-commercial prerelease**

## What changed and why

RC15 could fail Update with `INSTALL_UPDATE_FAIL=VENV_CORE_PROCESS_NOT_RUNNING` even when Python, its virtual environment and dependencies worked. Binary inspection confirmed the Swift GUI still looked up SMB credentials using the hardcoded account `user`, while the installer and engine used `config.json.username`. With only the correct configured credential present, the GUI refused to launch the engine; no Python traceback was required to produce the failure.

RC15.1 reads the existing configured username consistently in GUI, installer and Python. It does not fall back to `user`, create alternative credentials or modify an existing saved password automatically. Invalid configuration is rejected rather than silently reset; the configured remote root is preserved.

Startup now distinguishes GUI launch, helper launch, Python initialization, credential availability and process survival. Per-launch session tokens and fresh challenge responses reject stale evidence. A bounded deadline remains, but a process-name match or elapsed delay alone cannot prove success. Reported outcomes include `CREDENTIAL_NOT_FOUND`, `CORE_START_FAILED`, `CORE_EXITED`, `CORE_START_TIMEOUT` and verified success `CORE_VERIFIED`; GUI failures are reported separately. Clean installation without credentials reports `WAITING_FOR_CONFIGURATION`, not engine success.

Existing-installation credential preflight occurs before stopping the old app. Rollback also preserves/restores the GUI LaunchAgent, including its original absence. Installer result handling distinguishes waiting for configuration, verified startup and failure. SMB/Tailscale transfer logic, Finder integration and bundled dependency wheels remain unchanged; the engine only gains a startup-health callback. RC14 sanitization is preserved.

## Validation and its limits

- **10 native isolated startup cases PASS:** configured real account identity without generic credential, missing credential, generic-only credential, GUI/Python credential mismatch, backend error, 11-second delayed start, crash before initialization, crash shortly after initialization, missing helper and initialization timeout.
- **8 isolated lifecycle cases PASS:** verified update, clean-install configuration wait, partial runtime failure, crash rollback, timeout rollback, and missing credential/invalid configuration/missing Python before stopping the old app.
- **2 stale or wrong-session evidence cases PASS:** neither was accepted as a successful current launch.
- Swift identity/outcome checks, sanitization audit, transfer-code parity, package integrity and protected-file preservation checks **PASS**.

These tests used a fixture Keychain backend with the real configured account identity and a fictitious password. They did not use or change the real SMB password. Administrative/process-control boundaries and old-app relaunch were isolated in lifecycle tests; restoration of fixture files was real. **No administrative Update of the working installation, reboot or complete candidate SMB transfer was performed.** No TrueNAS change was made. Historical RC13 acceptance is not automatically promoted to RC15.1.

## Python and platform requirements

External **standard CPython 3.14** is required; this DMG does not embed a standalone interpreter or modify system Python. **No Homebrew dependency.** Native testing used MacPorts **3.14.8** on Intel macOS **26.7.1**. Explicit discovery of official python.org and Homebrew Python is retained, but those distributions were not natively retested. Declared minimum macOS is **15**, not yet validated for this candidate. Keep the selected external Python installed. Apple Silicon/Rosetta, Windows/Linux and arbitrary NAS deployments are not certified; universal configuration wizard and local/external destination backends are not implemented.

## Română — ce am făcut și de ce

RC15 căuta în interfața Swift parola contului fix `user`, deși installerul și motorul foloseau contul real din `config.json`. Acest dezacord împiedica lansarea motorului și producea eroarea de Update. RC15.1 folosește aceeași identitate configurată în toate cele trei componente, fără credential alternativ și fără modificarea automată a parolei existente.

Am înlocuit verificarea bazată pe simpla existență a procesului cu verificări distincte pentru aplicație, helper, Python, credential și răspunsuri proaspete ale motorului. Erorile sunt raportate separat; instalarea fără credential așteaptă configurarea. Preflight-ul verifică înainte de oprirea aplicației vechi, iar rollback-ul include LaunchAgent-ul. Transferul SMB/Tailscale și sanitizarea sunt păstrate.

**20 cazuri izolate au trecut**, plus verificările de identitate, sanitizare, paritate, semnătură și integritate. Keychain a fost simulat; parola reală și instalația funcțională nu au fost schimbate. **Update-ul real administrativ, reboot-ul și transferul complet cu noul candidat rămân de testat.** MacPorts 3.14.8 este verificat nativ; detectarea Python oficial/Homebrew este păstrată, fără validare nativă nouă pe acestea. Nu este un installer certificat pentru orice calculator și nu include Python autonom.

Aplicația, installerul și DMG-ul au notarizare Apple **Accepted**, ticket-uri validate și acceptare Gatekeeper. RC14 public rămâne disponibil în istoric; DMG-ul RC15 anterior nu a fost suprascris. Licența proprietară necomercială și drepturile componentelor terțe se păstrează; publicarea nu acordă drepturi generale de reutilizare a surselor. Sursele private de dezvoltare, logurile și profilele utilizatorului nu sunt publicate.
